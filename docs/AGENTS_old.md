# 開発エージェント向け指示

このファイルはリポジトリのルートに置くAGENTS.mdである。本プロジェクトの実装・修正・調査を行うエージェントに適用する。

## 目的と参照順序

ResolumeのColumnトリガーに連動し、制御用Effect Clipで指定したLayerのTransition設定およびMask Modeを変更するC++／FFGLプラグインを開発する。

最初にdocs/SPECIFICATION.mdを読む。ユーザーの指示を優先し、仕様との相違や新しい判断は仕様書へ反映する。本ファイルと仕様書の不整合を黙って実装で解釈しない。

文書作成時点では、ソースコード、ビルド設定、テスト、実機検証結果は存在しない。以下の構成・コマンドを既存のものとして扱わない。

## 守る要求

- 制御用Clipは説明用の仮称であり、正式な機能名はEffect Clipである。
- 変更対象はLayer Transitionの方式・時間とLayer Mask Modeである。
- Transition Blend ModeとLayer Blend Modeを混同しない。
- MaskのTarget Layerは、マスクされる側ではなくMask Modeを変更する側である。
- 利用者はLayer番号と意味のある選択肢を編集する。生のOSCアドレスや列挙番号を日常操作へ出さない。上級者向け詳細設定では、仕様書4.3節に従い制御項目のOSC対応を変更可能とする。
- Resolume本体は改造しない。
- Effect Clipの配置LayerとTarget Layerを独立して扱う。
- 同じColumnで始まる映像に、新設定が適用されるかを必ず検証する。設定値が後から変わるだけでは要求達成としない。
- Maskを通常表示へ戻す操作と、Mask設定を変更しない指定を分離する。
- 初版は1インスタンス1対象Layerとし、停止時の自動復元は行わない。

## 調査・報告の原則

- 「要求」「資料確認済み」「設計案」「実機確認済み」「未確認」を区別する。
- OSCアドレス、RESTフィールド、列挙値、ポート、SDKの通知仕様、ビルドコマンドを推測で確定しない。
- ffgl-effectテンプレートの実体・版・ライセンスは未確定である。名前からURLやファイルを創作しない。
- 公式資料と対象環境から取得した情報を優先する。参考情報には出典・対象版を残す。
- コンパイル成功、UDP送信成功、Resolume受信、設定反映、同一Columnの映像への反映を別々に判定する。
- 実機がない場合は実行可能な範囲を進め、未実施の試験と再現手順を残す。実機成功を報告しない。
- 不可能または未成立と判明した項目は理由と影響を記録する。代替方式を元の仕様達成と呼ばない。
- 既に認められた範囲の調査・実装・修正は進める。操作体系や構成を変える必要がある場合に、その差分を具体化して示す。

## 着手手順

1. 仕様書の未検証事項と既存の検証結果を確認する。
2. OS、Resolume製品名・版、SDKのcommit、コンパイラ、アーキテクチャ、テンプレートの実体を記録する。
3. 既存リポジトリがあれば構成・ビルド手順を読み、既存方式を優先する。
4. 外部テストツールでTransitionの方式と時間を変更できるか確認する。
5. 無送信の診断用FFGLでホスト通知とパラメータ復元を観測する。
6. トリガー識別・映像維持・通信の各成立を確認してから統合する。
7. Transition機能を検証後、Maskの3状態を調べて統合する。

各段階の合格条件は仕様書7節に従う。成立していない条件を後工程の実装量で埋め合わせない。独立して進められる調査は継続してよい。

## トリガー検出

- Connect／Disconnectや初回ProcessOpenGLをColumnトリガーと同一視しない。
- プレビュー、サムネイル、初期化、再初期化、パラメータ編集を実行契機にしない。
- 同一Columnの再トリガーは、設定値が同一でも別操作として扱う。
- 同じ値だからといって再適用を省略しない。別の操作で対象値が変わっている可能性がある。
- 初期化時やパラメータ復元中に制御コマンドを送らない。
- Auto Pilot、Fader Start、Bypass、Opacity 0、Solo、読込時自動再生の通知を個別に検証する。
- 秒数による間引きや無描画時間の推測で、1回だけの実行を保証したことにしない。
- FFGL単独で識別できなければ、その結果を明示し、必要な追加連携を設計変更案として扱う。

## 実装構成

FFGL Adapter、Trigger Detector、Control Request、Layer Controller、Protocol Mapping、Transport、Diagnosticsの責務を分ける。既存構成がある場合は、この分離を満たす最小の変更を選ぶ。

- トリガー時の値をスナップショット化し、実行中の編集と競合させない。
- 描画処理内でHTTP応答、ネットワーク待ち、ディスク書込み待ちを行わない。
- 毎フレーム送信しない。1トリガーにつき論理的要求1件を作る。
- 複数のプロパティを設定するための複数パケットと、重複実行を区別する。
- キューは有限とし、古い未送信要求が後のColumnの状態を上書きしないよう管理する。
- 終了時にワーカー・ソケット・GL資源を解放し、古い要求を送信しない。
- スレッド間共有の値とインスタンスの寿命を管理する。例外をホスト境界へ漏らさない。

## プロトコルと失敗処理

- 送信先は初版ではローカルの127.0.0.1とする。
- 受信ポートは対象環境で確認する。OSC受信等の有効化手順を導入資料に残す。
- 対象Layerの番号変換、値の型、Durationの単位変換、列挙値の対応を一か所に集約する。
- 絶対値設定を使い、Toggleや相対増減を使わない。
- 不明なBlend Mode、範囲外のDuration、不正なLayer番号を黙って補正しない。
- 送信前に判明した不正値があれば、その論理要求全体を送信しない。
- OSCのsend成功を適用成功と表示しない。読戻しがなければ「反映未確認」と扱う。
- UDPで受信側のexactly-onceや複数項目の原子性を保証しない。
- 自動再送は初版では行わない案である。追加する場合は上限・世代・遅延到着の扱いを設計する。
- 部分反映時の自動ロールバックは実装しない。失敗した範囲を記録する。
- 同一Columnから同じ対象・同じ項目への競合指示は初版の保証対象外とする。
- OSCで設定できない場合はRESTを調べる。存在するだけで対象項目を変更できると判断しない。

## 映像とMask

- 入力テクスチャの色・Alpha・向き・サイズを保つパススルーを第一候補とし、GL状態を復元する。
- 透明出力だけでEffect Clipを無害化できると考えない。
- 配置Layerで既存Clipが置き換わることを考慮し、最初は制御用の配置Layerを確保する。
- Opacity 0やBypassでもプラグインが処理されると仮定しない。
- One Belowの作用先、All Belowの範囲、Group境界を実機で確かめる。
- Mask Mode変更は、マスク用Clipの選択・再生を代行する機能ではない。
- 通常映像と独立したMask動画を同一Layerで同時に扱う機能を追加したことにしない。
- Mask Mode切替と映像切替の前後関係を観測し、一瞬の露出も評価する。
- LayerやGroupの削減は構成上の効果として評価する。削減を無条件に保証しない。

## 保存と互換性

- FFGLパラメータの番号・型・列挙値の意味を、公開後に不用意に変更しない。
- Compositionの保存・再読込、Clip複製、Preset保存・再適用をそれぞれ確認する。
- 接続状態や送信済みフラグを永続化しない。
- ホスト版で候補一覧が変わる項目は対応範囲と互換性を明示する。

## 検証と記録

仕様書のAT-01〜AT-15を受入試験として使う。ホスト動作が関係する項目をモックだけで合格にしない。

ユニットテストを追加する場合は、値の変換、要求重複の抑止、同一Column再トリガー、古い要求の破棄等、故障の影響が大きいロジックを対象とする。文書だけの変更や実装をそのまま写したテストは不要。

検証資料は必要になった時点で以下へ追加する。これらは現時点では未作成である。

| パス案 | 内容 |
| --- | --- |
| docs/VALIDATION.md | 対象環境、試験手順、期待結果、実結果、制限 |
| docs/PROTOCOL_MAP.md | 実測済みのアドレス・API項目・型・単位・列挙値 |
| docs/SETUP.md | 確認済みのビルド、導入、接続、復旧手順 |

ビルド手順は実際の構成を読んでから確定する。実行していないコマンドや存在しないターゲットを「確認済み」として書かない。
