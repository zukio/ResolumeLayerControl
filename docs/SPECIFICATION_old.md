# Resolume Layer設定制御プラグイン 仕様・設計書

文書版：0.1 ／ 作成日：2026-10-22 ／ 状態：検証前の設計案

### 2026-10-23 方針更新（以下の旧OSC優先案より優先）

ユーザー指示により、PluginとResolume間はWebSocket受信・送信に統一する方針とする。既存の外部OSC連携は妨げない。旧PRE-03、4.3節のOSC専用詳細設定、TransportのOSC優先記述は旧案として扱い、WebSocketのパラメータ対応へ改訂する対象とする。OSC互換性維持を目的に送信経路を残さない。

Arena 7.27.1で利用者がNode-REDからTransition Blend Mode、Duration、Mask Modeの3状態の変更成功を報告。Blend ModeとMaskはCompositionから取得したパラメータID指定、Durationは `/composition/layers/3/transition/duration` のsetで成功。IDは固定値として実装しない。設定変更成功と同一Column映像への適用順序は別判定とする。

FFGL通知の既存実測を再調査するよりWebSocketの検証を優先する。WebSocketの17回操作試験の通知件数は操作数と一致したが、誤検出除外と操作対象識別は未成立。詳細はTRIGGER_RESEARCH.md末尾を参照。

本書は依頼者の構想を実装・検証に渡すための文書である。要求、資料で確認できた事実、設計上の選択、未検証事項を区別する。診断用FFGL試作と通信ワーカー単体試験を追加した。利用者の実機で試験OSC受信を確認したが、Connect方式では同一Column再トリガー時の受信がなく要求未達成。追加通知の記録を実装し、実機検証を待つ。Windowsのビルド条件は未記録。追加通知版の実機試験、Transition・Mask制御試験は未実施。現状と再現手順は[VALIDATION.md](VALIDATION.md)を参照する。

## 1. 目的と完成条件

ResolumeのColumnをトリガーすると、そのColumnに置いたEffect Clipの設定に従って、指定LayerのTransition設定およびMask Modeを変更する。設定内容はResolumeのパラメータUIで編集・保存し、本番中の手動操作を減らす。

本来の完成条件は、Columnを1回操作すると、そのColumnの映像切替に必要な設定が適用されることである。「トリガー後に値だけが変わり、同時に始まった映像には旧Transitionが使われる」状態は、この完成条件を満たさない。

Mask制御は、同じLayerを場面によって通常映像用とマスク用に切り替え、役割の切替だけのために用意していたLayerやGroupを減らすことを目指す。削減可能な数は構成によるため保証しない。

## 4. 機能仕様

### 4.1 Transition制御

有効なトリガーを受けた時点の設定を取り出し、Target LayerのTransition Blend ModeとDurationを変更する。Layer同士を合成するBlend Mode、LayerのOpacity、対象Clipの速度等は変更しない。

Blend Mode候補は対象版で確認した一覧を使う。表示名と外部制御値の対応を明示し、不明な値をAlpha等へ黙って置き換えない。Randomや追加Mixerへの対応は一覧と保存互換性を確認してから対応範囲へ加える。

DurationはUI・内部モデルとも秒として扱う。送信時に必要な単位変換や正規化は通信側で行う。0秒、上限、精度を対象版で確認する。マニュアルのスライダー例だけからAPIの有効範囲を決定しない。

### 4.2 Mask Mode制御

| 要求上の指定 | 意図する動作 |
| --- | --- |
| Disable | Target Layerを通常の映像Layerとして扱う |
| One Below | Target Layerの内容を、その直下のLayerのマスクとして使う |
| All Below | Target Layerの内容を、下位Layer群のマスクとして使う |

制御対象は、マスクされる映像Layerではなく、Mask Modeを持つLayerである。Mask Mode変更だけでマスク用素材の選択・配置・再生は行わない。

#### 目的と制約

- 同じLayerを場面Aでは通常映像、場面BではMaskとして使う場合に、役割切替用の重複構成を減らす。
- 同じLayerに、独立した通常映像と独立したMask動画を同時再生する機能は追加しない。
- One Belowは直下を対象とする。離れた任意のLayerを選ぶ機能にはしない。
- Group境界、入れ子、Layerの移動後の適用範囲は実機で確認する。Groupを不要にできると断定しない。
- Layerの順番を変えると、Maskの作用先も変わり得る。番号の割当と下位関係を再確認する。
- Mask切替の瞬間とClip切替の瞬間の前後関係によって、旧映像が一時的に通常表示される等の可能性を検証する。
- 動画のマスク結果は、黒・白・中間調・Alphaを含む素材で確認する。
- 動画対応のOne Below専用MASKエフェクトは別の代替案として扱う。本プラグインのMask Mode切替と同等とはみなさない。
- Maskの外部制御が実現しなくても、成立済みのTransition機能は独立して評価できる。ただしMask対応済みとは報告しない。

### 4.3 パラメータ案

1プラグイン内にTransitionとMaskをまとめる初期案とする。第1試作はTransitionの3項目と最小限の実行制御を優先する。

| 表示名案 | 型・意味 | 初期状態案 |
| --- | --- | --- |
| Enabled | 制御の有効／無効 | 無効。配置・初回読込だけで送信しない |
| Target Layer | 利用者が認識するLayer番号の整数 | 1。ただしEnabledが無効なら送信しない |
| Apply Transition | Transitionの変更有無 | 有効 |
| Blend Mode | 検証済み候補から選ぶ列挙値 | Alpha。対応値未確定なら送信不可 |
| Duration | 秒数 | 1.000秒。範囲・精度は検証後に確定 |
| Apply Mask | Mask Modeの変更有無 | 無効 |
| Mask Mode | Disable／One Below／All Below | Disable |

初期値、Enabled、2つのApply指定は追加した設計案である。Apply Mask無効は「変更しない」を意味し、Disableへの切替とは異なる。両方のApplyが無効なら送信しない。

OSC受信ポート等の接続設定は詳細設定へ集約する案とする。ポート番号は対象環境の設定を利用し、未確認の既定値を固定しない。Clipごとの設定として保存するか、共通設定とするかは試作後に確定する。

#### 上級者向けOSC設定

通常操作では確認済みの標準対応表を使用し、Layer番号と意味のある選択肢だけで設定できるようにする。上級者向けには、Transition方式・Duration・Mask ModeのOSCアドレスと送信値の対応を変更できる詳細設定を設ける。

以下は具体化のための設計案とする。

- 変更対象は本プラグインが扱う制御項目のアドレス、引数の型、単位変換、列挙値の対応とする。Target Layer番号の扱いも対応表へ集約する。
- カスタム設定は明示的に有効化し、標準設定へ戻せるようにする。既存の保存値の意味を変えず、標準対応とカスタム対応を区別して保存する。
- 編集や読込みだけでは送信せず、次の有効トリガーで設定をスナップショット化する。不正な対応があれば論理要求全体を送信しない。
- カスタム設定は実機確認済みの標準対応とは区別し、利用者が変更しただけでは反映確認済みと表示しない。
- 送信先は127.0.0.1のままとし、任意項目へのコマンド追加、Toggle、相対操作、スクリプト実行は初版に含めない。

詳細設定のUI、保存先・共有範囲、設定形式、検査可能な範囲は試作時に確定する。

Target Layerは初版では番号指定とし、Layerの移動・挿入・削除に追従するID指定とは区別する。Groupを含む番号とAPIのindexの対応、表示順、1始まり／0始まりは試験で確定し、変換を一か所に集約する。

### 4.4 トリガーと状態の扱い

| 操作 | 期待する制御 |
| --- | --- |
| 有効なColumnトリガー | 有効なApply項目を1回適用 |
| 同一Columnの再トリガー | 値が同じでも、新しい操作として1回適用。手動変更後の再トリガーで指定値へ戻すため、「現在値と一致なら省略」は採用しない（利用者確認 2026-10-23、AT-04維持） |
| 制御用Effect Clipの直接トリガー | 通常のClip操作と整合する形で1回適用 |
| Clip選択、プレビュー、サムネイル生成 | 適用しない |
| パラメータ編集、Enabled切替 | それだけでは適用しない。次の有効トリガーで使用 |
| Clip停止・Eject・別Clipへの切替 | 自動復元しない。次の制御指示がなければ変更済みの値を保持 |
| 再描画、Bypass復帰、解像度変更等 | それだけでは適用しない |
| 保存・読込 | それだけでは適用しない。読込後に実際の自動トリガーが起きる場合は別途検証 |

1回の設定適用はBlend ModeとDuration等の複数コマンドになり得る。各フレームで送らず、1トリガーにつき論理的な変更要求1件を生成する。

同じ値の再適用も必要である。途中で人や別の制御がLayer設定を変更した場合に備え、「直前と同じパラメータだから送信しない」という省略はしない。

## 5. 設計案

### 5.1 責務の分離

| 要素 | 責務 |
| --- | --- |
| FFGL Adapter | ホストからの通知、パラメータ入出力、入力映像の維持 |
| Trigger Detector | 本番の起動を識別し、重複とプレビュー等を除外 |
| Control Request | 対象Layerと適用値をトリガー時点で固定して保持 |
| Layer Controller | 値の検査、項目別の制御要求の生成 |
| Protocol Mapping | 確認済みのアドレス・型・単位・列挙値への変換 |
| Transport | OSC送信、必要時のREST処理、失敗の記録 |
| Diagnostics | トリガー、送信、反映確認、失敗を区別して記録 |

通信処理を描画ロジックへ埋め込まない。ネットワーク待ち、HTTP応答待ち、ファイル書込み待ちを描画スレッドで行わない。ワーカー等を使う場合はキューに上限を設け、終了時のキャンセルと資源解放を行う。

### 5.2 処理手順

1. パラメータを復元する。この段階では送信しない。
2. 検証済みの方法で有効なトリガーを識別する。
3. Target Layer・有効項目・値をスナップショット化する。
4. 範囲・対応値・通信設定を検査する。判明している不正値があれば要求全体を送信しない。
5. 確認済みのプロトコル対応で変更要求を送る。
6. 送信結果を記録する。読戻しできる場合は一致を別に記録する。
7. Clip停止時には設定を自動復元しない。

Layerが存在するかの事前照会が必要かは、外部APIの取得可否と遅延を踏まえて決める。未確認の番号に対し別のLayerを代用しない。

### 5.3 トリガー検出の成立判定

Connect／Disconnectは候補となる通知である。しかしSDKにメソッドがあることは、Columnトリガーとの1対1対応の証明にはならない [S7]。

まず送信を行わない診断用試作で、生成・初期化・接続・描画・切断・パラメータ変更の順序を記録する。次を実機で識別できるか調べる。

- 別Columnへの切替と、再生中の同一Columnへの再トリガー。
- プレビュー、初回ロード、GL再初期化、Bypass、Opacity 0、Solo等による処理省略。
- Auto Pilot、Fader Start、読込直後の自動再生が有効な構成。
- 旧制御Clipと新制御ClipがTransition中に共存する場合。
- 連続トリガー中にパラメータを変更した場合。

初回ProcessOpenGLだけの送信や、Connectごとの無条件送信を完成方式として固定しない。無通信フレーム数やタイマーによる推測だけで再トリガーを保証しない。

純粋なFFGL通知で識別できなければ「検出不成立」と記録する。ホスト側イベント連携等を比較し、追加の常駐アプリや操作変更が必要なら構成変更案として示す。

追加情報の調査は[TRIGGER_RESEARCH.md](TRIGGER_RESEARCH.md)に記録する。OSC出力、パラメータアニメーション、WebSocketを候補として比較し、まず受信専用ツールでOSC出力を観測する。追加連携方式の採用や操作体系の変更はまだ確定していない。

2026-10-22追記：対象Arena 7.27.1で同一Column再操作に対応するOSC出力を観測した（上記調査記録の実機結果）。既存の外部OSC連携を妨げないことを追加の要求とし、内部・外部への同時出力、中継、別経路を比較する。公式資料ではBroadcastは確認できたが、内部・外部に異なる宛先を個別登録して同時送信する機能は未確認。同時受信と製品への統合は未検証であり、方式は未採用。

### 5.4 同一Columnでの反映順序

想定したい順序は「設定有効化 → 対象映像のTransition開始」である。一方、実装候補は「Column起動 → FFGL処理 → ローカル通信 → Resolumeで設定処理」となり、間に合わない可能性がある。これは設計上の懸念であり、発生を実測した事実ではない。

最初のTransition試験で、新旧の時間と方式を明確に変えて比較する。値のUI表示や送信成功だけで合格にしない。送信順序やOSC Bundleも、映像開始前の適用や複数項目の原子性を保証する根拠にはしない。

間に合わない場合は、事前設定用のColumn、設定後に映像を起動する制御、別の連携方式を代替案として整理する。いずれも操作または構成の変更を伴うため、本来の完成条件とは分けて記載する。固定時間待ちの追加だけで成立済みとしない。

### 5.5 映像出力と配置

本プラグインは映像加工を目的としない。Effect Clipは下位Layerの映像へ作用するため、FFGL Effectとして受け取ったテクスチャを色・Alpha・向き・解像度を維持して返す方式を第一候補とする。

透明画素を出すだけで映像への影響をなくせるとは仮定しない。Effect Clipでは映像を置き換えてしまう可能性も評価する。OpenGL状態を適切に復元し、入力なしの扱いはSDK契約に従って検証する。

配置Layerでは元から再生中のClipを置き換える可能性がある。初期試験は専用の配置Layerを用意する。既存映像Layerへ置いても停止しないとは記載しない。配置LayerのOpacity 0やBypassによってFFGL処理が省略される可能性があるため、非表示化をトリガー成立の前提にしない。

### 5.6 通信・失敗時の扱い

- コマンドは絶対値の設定を使う。Toggleや次の値への切替で再送の影響を増やさない。
- アドレス、型、Duration変換、Blend ModeとMask Modeの対応値を実測記録へ残す。
- UDP送信の成功と、Resolumeに届いて設定が反映されたことを区別する。
- OSC／UDPだけで受信側のexactly-once実行を保証したとは報告しない。重複抑止は要求生成側の責務とし、反映保証には別の観測が必要である。
- 初版は失敗時の自動再送を行わない案とする。再送が必要なら上限と古い要求の破棄方法を定める。
- 複数項目の一部だけが反映される可能性を扱う。原子的更新や自動ロールバックは保証しない。
- 後のColumnを起動した後に、古い要求の再試行で設定を戻さない。キュー内の未送信要求は世代で管理し、既送信分を取り消せないことも区別する。
- 同じTarget Layerの同じ項目を、同一Column内の複数インスタンスから変更する構成は初版の保証対象外とする。実行順に依存させない。
- 切断、ポート不一致、非対応項目等はログに記録し、Resolumeの描画を停止しない。
- RESTが使えない場合にOSCへ、あるいはその逆へ、未確認のまま自動切替しない。

## 6. 保存と互換性

FFGLパラメータをResolumeに保持させる方式を第一候補とする。Compositionの保存・再読込、Effect Clipの複製、Presetへの保存・再適用について個別に検証する。

公開後はパラメータの番号・型・既存列挙値の意味を不用意に変えない。Blend Mode一覧がResolumeの版や導入Mixerで変わる場合は、対応表と保存互換性の方針を定める。未知の値は送信不可として明示する。

実行中フラグ、接続状態、実行世代、送信済み判定は保存値に含めない。

## 7. 開発段階と判定

| 段階 | 作業 | 次へ進む条件 |
| --- | --- | --- |
| 0：環境確定 | OS、製品・版、SDK、テンプレート、ビルド手順、テストCompositionを記録 | 第三者が同じ条件で試験できる |
| 1：Transition制御確認 | 外部テストツールから方式・時間を変更し、同一Columnへの反映順序を調べる | UNK-02とUNK-05の結果・制約が明確 |
| 2：診断用FFGL試作 | パラメータUI、描画維持、ホスト通知ログ、UDPの別試験を作る | UNK-01、04、06、07の成立可否が明確 |
| 3：Transition統合 | 制御要求と通信を統合し、Columnから実行する | Transition関連の受入試験に合格 |
| 4：Mask制御確認・統合 | 3状態、通常表示への復帰、動画、Group境界を試験する | Mask関連の受入試験に合格 |
| 5：運用整理 | 対応表、導入手順、制限、実測結果をまとめる | 保証する構成と未対応事項が明示されている |

2026-10-22のユーザー指示により、先に独立した診断用FFGLでOSC送信と通知の観測を進める。Transition制御の成立判定を省略せず、通知識別が未成立の間は製品用トリガーとして統合しない。

第1段階でFFGL連動のタイミングを断定しない。外部制御の順序試験と、第2・3段階の実際のFFGL経由試験を区別する。

## 8. 受入試験

全項目、文書作成時点では未実施。対象環境で成功した範囲を対応範囲とする。

| ID | 試験 | 合格条件 |
| --- | --- | --- |
| AT-01 | 別Layerを指定してTransition変更 | 対象の方式・時間だけが変わり、Layer Blend Modeや他Layerの設定を変えない |
| AT-02 | 旧設定から異なる新設定へ同じColumnで切替 | 今回開始するTransitionから新しい方式・時間が使われる |
| AT-03 | 1回のトリガー後に描画を継続 | 論理要求1件のみ。毎フレームの送信がない |
| AT-04 | 同一Columnを続けて再トリガー | 操作ごとに1件。途中で手動変更した値も指定値へ戻る |
| AT-05 | プレビュー・選択・再初期化・編集 | これらの操作だけでは制御要求を生成しない |
| AT-06 | 保存・再起動・読込・複製・Preset再適用 | パラメータが保持され、他インスタンスから独立する |
| AT-07 | パススルー比較 | 無制御時と比較し、色・Alpha・向き・解像度に意図しない差がない |
| AT-08 | Clip停止・別Clip切替・空セルのColumn | 不要な自動復元や追加送信がない。空セル時のホスト挙動も記録する |
| AT-09 | Maskの3状態を相互に切替 | 通常表示・直下のみ・下位群が仕様どおりに切り替わる |
| AT-10 | Mask動画と同一Columnの映像切替 | 動画が更新され、旧素材や通常表示の意図しない一瞬の露出がない |
| AT-11 | Group境界、Layer移動・挿入・削除 | 作用範囲と番号対応を説明でき、対応保証範囲が定まる |
| AT-12 | 通信無効・不正値・非対応値 | 誤った別対象へ送らず、失敗・未確認を記録し、クラッシュしない |
| AT-13 | 高速切替と旧新制御Clipの重なり | 重複や未送信の古い要求による上書きがなく、実測した追従限界を記録する |
| AT-14 | Opacity 0、Bypass、Solo、Auto Pilot等 | 成立する条件と成立しない条件を記録し、保証範囲に反映する |
| AT-15 | 負荷・繰返し・終了 | 合意した運用時間・切替頻度で資源増加や送信の滞留がなく、終了できる |

送信回数はログと受信観測で確認する。反映結果はUI値・取得値・実映像を使い分ける。Duration精度、許容遅延、連続運転時間、連打間隔の数値基準は運用条件を確認後に記入し、未設定のまま性能保証を出さない。

## 9. 検証記録の書式

各試験には、試験ID、日時、OS、Resolume製品・版、SDK／プラグインのcommit、配置と対象Layer、操作手順、期待結果、実結果、送信先、型・値、ログ・映像の場所、判定、制限を記録する。

プロトコルの対応表には、機能、対象版、実アドレスまたはAPI項目、HTTPメソッド等、値の型、単位、列挙対応、読戻し方法、実機確認日を残す。未確認の欄は「未確認」とし、推測値で埋めない。

## 10. 初版の範囲外

Resolume本体改造、本プラグインの制御項目以外へ任意のOSCコマンドを追加するUI、ネットワーク越しの複数PC制御、1インスタンスでの複数Target Layer指定、旧値への自動復元、独立した通常映像とMask動画の同一Layer同時再生、専用動画MASKエフェクト、未検証バージョンへの互換性保証は初版に含めない。
